## 0. 한 줄 스토리

> **"이론적으로 가장 어려운 부류(완전정보로도 NP-complete, 제한통신이면 결정불가능)에 속하는 협동 게임을,
> '풀 수 있는 형태의 연구 질문'으로 환원한 뒤, 강화학습이 어디까지 배우는지를 *천장 측정*이라는
> 측정 가능한 방법론으로 추적한 프로젝트."**

발표를 관통하는 3개 메시지:

1. **문제 정의** — The Crew는 *완전정보로도 NP-complete*, *통신이 제한되면 결정불가능*. "전체를 한 번에 푼다"는 접근은 애초에 성립하지 않음 → **연구 질문을 좁히는 것이 필수**.
2. **환경 모델링** — 50개 미션/특수규칙을 다 넣는 건 *난이도가 아니라 콘텐츠 다양성*. 어려움의 핵심(은닉정보 하 협력 + 제한된 통신)만 보존한 **최소 커널**(`드래프트 + 트릭테이킹 + 통신토큰`)을 의도적으로 분리 = **의도된 환원(reduction)**.
3. **학습 과정·결과** — "됐다/안됐다"가 아니라, **천장(상한)을 먼저 측정**해 *"과제가 원래 어려운가 vs RL이 못 배우는가"* 를 분리하고, 병목을 **'드래프트 미학습'**으로 특정한 뒤 가설–개입을 반복(과학적 방법론).

## 1. 대상 게임 — The Crew

- 4인 **완전 협동** 트릭테이킹. 경쟁이 아니라 **팀 전원이 함께 이기거나 함께 진다.**
- 카드 40장 = 색 4종(Yellow/Blue/Green/Pink) × 1~9(36장) + **로켓(트럼프) 1~4(4장)**.
- 각 플레이어는 **자기 손패만 본다(부분관측)**. 다른 사람 패는 모름.
- **사령관(함장)** = 로켓 4번 소지자. 첫 트릭의 선(lead).
- 미션마다 "특정 카드가 든 트릭을 지정된 사람이 이겨라" 같은 **과제(task)** 가 배분되고, 하나라도 어그러지면 **즉시 미션 실패**(all-or-nothing).
- 결정적 제약: **명시적 대화 금지**. 미션당 단 1회, 트릭 사이에만, "내 카드 1장 + 최고/최저/유일"이라는 극도로 제한된 **통신 토큰**만 허용.

### 트릭테이킹 기본 규칙
- 로켓(트럼프)은 어떤 색도 이긴다. 로켓끼리는 높은 숫자가 승(4로켓이 최강).
- 선 색상(lead suit)을 가지고 있으면 반드시 따라내야 한다(**follow-suit**).
- 트릭 승자가 다음 트릭의 선이 된다.

> 원래 *딥 씨 크루(심해 탐험)* 기반이었으나, 강화학습에 더 적합한 **스페이스 크루**로 마이그레이션함.
> 룰 상세: [`../the_crew_rules_ko.md`](../the_crew_rules_ko.md), 미션 정의: [`../the_crew_missions_ko.md`](../the_crew_missions_ko.md).

## 2. 왜 어려운 문제인가 — 이론적 근거 (인용)

| 논문 | 결과 | 함의 |
|---|---|---|
| **Reiber (2021), "The Crew is NP-Complete"** (UC Irvine) | 모든 패가 공개된 **완전정보 버전조차** 일반적으로 **NP-complete**. 특정 수트 분포 제한 시에만 다항시간 해 존재. | 정보가 다 주어져도 최적해 탐색이 본질적으로 어렵다 → RL이 최적 정책을 찾기 어려운 **이론적 하한**. |
| **Coulombe & Lynch (2022), "Decidability of FSA Team Games with Communication"** (MIT/Waterloo) | The Crew·Hanabi·The Mind류 **부분관측 협동게임**에서 **통신 대역폭이 행동 대역폭보다 좁으면 게임이 결정불가능(Undecidable)**. | 게임이 준 "제한된 통신 토큰"이 **협력 학습을 본질적으로 어렵게 만드는 구조적 장벽**. 우리 결과의 통신 무력화 현상과 직결. |

➡️ **결론:** The Crew는 *완전정보로도 어렵고(NP-complete)*, *제한통신에서는 결정 불가능*한 부류. **"전체 게임을 통째로 RL로 푼다"는 목표 자체가 비현실적** → 연구 성립을 위해 문제를 원리적으로 좁혀야 함.

### 연구 질문
> **"은닉정보 하의 협력이라는 The Crew의 어려움의 핵심만 남긴 최소 환경에서, 다중 에이전트 강화학습(MA-POCA)은
> 협력 정책을 어디까지 학습할 수 있는가? 그리고 그 한계(천장)와 병목은 무엇인가?"**

## 3. 환경 모델링 — 의도된 환원

### 3-1. 전체 게임 구성 요소
- ① **드래프트(과제 배분)** — 누가 어떤 과제를 맡을지 선택
- ② **트릭테이킹(플레이)** — follow-suit·트럼프 규칙의 협력 플레이
- ③ **통신 토큰** — 제한된 정보 공유 채널
- ④ 조난신호(카드 전달), 순서 토큰, 50개 미션별 특수규칙(9 금지·로켓 오름차순·사령관 첫·마지막 등), 사령관 결정/분배 …

### 3-2. 학습 대상으로 삼은 "핵심 커널"
✅ **① 드래프트 + ② 트릭테이킹 + ③ 통신 토큰**만 학습 루프에 넣음.
🔴 ④(조난신호·순서토큰·미션별 특수규칙 등)는 **관측 슬롯만 예약(헤드룸 확보)** 하고 **현재 학습에서는 끔.**

### 3-3. 의도된 환원의 4가지 근거
1. **어려움의 본질을 그대로 담는다** — 논문이 지목한 어려움 = ⓐ 은닉정보 하 협력(트릭테이킹) + ⓑ 제한 통신(통신토큰) + ⓒ 조합적 자원 배분(드래프트). 이 셋이 NP-complete·결정불가능을 *만들어내는* 메커니즘. *쉬운 부분을 골라낸 게 아니라 어려움을 만드는 부분만 남겼다.*
2. **나머지는 난이도가 아니라 콘텐츠 다양성** — 50개 미션 특수규칙은 같은 트릭테이킹 엔진 위 변주(reskin). 다 넣어도 학습 문제의 *종류*가 아니라 *경우의 수*만 늘어 연구 질문을 흐림.
3. **과제를 원자 단위로 일반화** — 모든 미션 과제는 본질적으로 **"지정 카드가 든 트릭을 이겨라(`WinSpecificCard`)"** 의 조합. 이 단일 원자 과제를 `num_tasks`(N)개로 두는 커리큘럼으로 환원.
4. **확장 가능한 설계로 환원을 되돌릴 수 있게** — 관측 벡터를 **최종 313차원으로 미리 고정**(특수규칙 32칸 예약). 나중에 특수규칙을 켜도 신경망 크기 불변 → `--resume`로 점진적으로 전체 게임에 다가갈 수 있음(= 단계적 로드맵의 1단계).

### 3-4. task 수를 N=1~4로 한정한 이유 (학습가능 경계)
- 실제 The Crew 미션당 과제 수는 평균 **≈5**, 최대 **10**. 우리 학습은 **N=1~4**(혼합 시 평균 ≈2).
- **자체 천장 측정상 N≥5는 all-or-nothing 보상에서 미션 성공 천장 ≈0%** → 학습 신호가 바닥 밑 → 어떤 정책도 의미 있게 못 배움. (천장: N=1 54% → N=2 22% → N=3 7.7% → N=4 2.5% → N≥5 ≈0%)
- 따라서 N=1~4 = **"신호가 존재하는 학습가능 범위"**. 게으른 스코핑이 아니라 *측정으로 확인한 경계*.

### 4-3. 보상 (MA-POCA 그룹)
- task 완수 **`+1/N`**(정규화, Run7~) / task 실패 **`−1`**(즉시 미션 종료).
- 전부 완수 시 +1.0(N무관) → 에피소드 리턴 범위 ≈ [−1, +1].
- **리턴 해석 공식 (N=1):** `Group Reward = 2·미션성공률 − 1`. (−0.5=25% / −0.24=38% / 0=50% / +0.087=54%천장 / +0.84=92%)
- 드래프트·플레이 두 정책의 크레딧 할당은 POCA 중앙집중 critic이 담당.

### 4-4. 커리큘럼
- `num_tasks`(N)를 1→4로 점증. 진급 기준은 초기엔 그룹 평균 보상(`measure: reward`), 후기엔 `measure: progress`로 전환.

## 5. 방법론 ① — 천장 측정 (Ceiling Measurement) · 프로젝트 하이라이트

RL이 성공률 ~38%에서 정체했을 때 원인 가설은 둘:
- **(가) 과제가 원래 어렵다** → 사람이 짠 규칙기반 정책도 비슷하게 낮을 것.
- **(나) RL이 학습을 못 한다** → 규칙기반은 훨씬 높을 것.

이를 가르려고 **게임 규칙을 순수 파이썬으로 충실히 재현**([`../ceiling_test/ceiling_sim.py`](../ceiling_test/ceiling_sim.py))해 사람이 설계한 여러 정책의 성공률(=천장)을 **2만 딜**(시드 42 고정)로 측정. (Unity는 헤드리스 대량 시뮬이 번거로워 파이썬으로 분리)

### 5-1. 단일 task 천장 사다리 (N=1, 2만 딜)

```
24.9%  무작위 (바닥선)
37.8%  협력플레이 + 랜덤 드래프트     ◄── RL 실측(~38%)이 정확히 여기
54.6%  협력플레이 + 자기손패 드래프트   ◄── 부분관측에서 학습 가능한 천장
91.9%  협력플레이 + 완전정보 최적 드래프트 ◄── 완전정보 구조적 상한
```

- `owner_score(hand, target)` = `2.0·(로켓 수) + 0.2·(최고 로켓값)` + (타깃 보유 시 `1.0 + 0.4·타깃값`) / (미보유 시 `1.2·(타깃을 이길 카드 수)`). threshold 스윕 최적 = 6.0 → 54.6%.

### 5-2. 다중 task 천장 (coop + 자기손패 드래프트 th=6.0)

| N(task) | 평균 그룹 리턴(비정규화) | 미션 성공률 |
|---|---|---|
| 1 | 0.087 | **54.4%** |
| 2 | 0.068 | **22.2%** |
| 3 | 0.120 | **7.7%** |
| 4 | 0.231 | **2.5%** |

> 정규화(+1/N) 재측정: N=1 +0.087 / N=2 −0.355 / N=3 −0.575 / N=4 −0.674 (단조 감소).

### 5-3. 핵심 해석
1. **RL(38%) ≈ coop+랜덤owner(37.8%)** — RL은 **협력 플레이는 학습**, **드래프트는 거의 랜덤.** 트릭 플레이·관측·RL 학습능력 문제가 **아니다.**
2. **38→55(+17pp)는 자기 손패만으로 가능** — 드래프트는 **학습 가능한 레버**.
3. **55→92 갭은 정책이 아니라 정보 문제** — 4명 패를 비교해야 가능한데, **통신은 트릭 사이(플레이)에만 쓰고 드래프트엔 못 쓰므로** → **55%가 부분관측 진짜 천장.** (Coulombe-Lynch 통신장벽과 정합)
4. **커리큘럼 임계값 버그** — 기존 threshold 0.6/0.8/1.0은 측정 천장(최대 0.23)을 전부 초과 → **전 스테이지 도달 불가** → Run1~3이 같은 데서 정체한 원인.
5. **measure=reward는 잘못된 진급 지표** — N↑에 성공률은 폭락하는데 평균 리턴은 비단조 → 부분점수가 난이도를 가림.

## 7. MCTS 라인 (`mcts` 브랜치 `ceb588a`) — SO-ISMCTS 협력 AI / 근사 최적 베이스라인

> RL이 *학습으로 협력을 창발*하는지 보는 게 주 질문이라면, MCTS는 **근사 최적 베이스라인**으로
> 천장(상한)을 Unity 환경 내에서 직접 측정하는 라인. (파이썬 `ceiling_sim`의 Unity 대응물)
> 세부: mcts 브랜치의 [`MCTS_Cooperative_AI.md`](MCTS_Cooperative_AI.md)(알고리즘) · [`MCTS_DESIGN_NOTES.md`](MCTS_DESIGN_NOTES.md)(의사결정·실험 로그).
>
> **확정 베이스라인(협력 2-task): 평균 완수 ~50% / 미션 ~35% — RuleBased(HFSM) 대비 완수 2.5배·미션 5배.**

### 7-1. 알고리즘: SO-ISMCTS (Single-Observer Information Set MCTS, Cowling et al. 2012)
초기엔 **앙상블 PIMC**(결정화별 독립 트리 → 평균)였으나, *strategy fusion*(남의 패를 안다고 가정하는 비현실적 낙관)과 *budget 분산* 문제로 **SO-ISMCTS로 전환**(주석/문서 명칭도 정정). 세 축:
1. **단일 공유 트리** — 여러 번 패를 추측(결정화)해도 **하나의 카드키 공유 트리**에 결과 누적 → 탐색 깊이 확보.
2. **가용성 인지(availability-aware) UCB** — 불완전정보에선 어떤 카드가 추측마다 낼 수 있/없을 수 있음 → "그 카드를 낼 수 있었던 횟수"로 UCB 보정.
3. **능동적 협력 롤아웃** — 성능의 대부분이 여기서 나옴(아래 7-3).

### 7-2. 신념 결정화 (`Determinizer.cs`)
밝혀진 모든 제약을 지키며 상대 손패를 분배:
- 제약: `selfHand`(내 패) · `playedCards/tableCards` · **`knownVoids`**(follow-suit 실패 = 그 수트 없음) · **`commReveals`**(통신 공개: 카드+최고/유일/최저 위치).
- **MCV(Most-Constrained-Variable) + 백트래킹** — 제약이 가장 심한 카드부터 분배, 모순 시 백트래킹(완전탐색에 가까움 → 항상 유효 분배 도달).
- `K=5`(`RedeterminizeEvery`)마다 1회 재샘플(다양성↔속도 균형), determinizations=10.

### 7-3. 협력 롤아웃 정책 (`MCTSRollout.cs`) — 핵심 레버
결정화 상태에선 모든 패를 안다고 가정 → 완전 협력 로직. 카드 결정(`Decide`) 우선순위:
1. **테이블에 미완수 목표가 깔림** — 내가 owner면 무조건 획득(이길 수 있는 최약 카드), owner 아니면 **가로채지 않게(Yielding)** 가장 안전·약한 카드.
2. **동료가 이기는 트릭에 목표 흘려주기(Release)** — 내 손에 *그 동료의 목표 카드*가 있으면 슬쩍 내서 동료가 먹게.
3. **내 목표를 보장 승리로 직접 처리(Lead Own Target)** — 내가 선이고 내 목표가 그 수트 최고/보장승리면 리드해 직접 챙김.
3.5. **능동적 피딩(Active Feeding) — 구조적 천장을 부순 핵심** — 내 목표가 *동료 손*에 있고 너무 약해 혼자 못 이길 때, 내가 그 수트의 **보장 승리 카드를 미끼로 리드** → 동료가 2순위(Release)로 목표를 흘림 → 내가(=임무 주인) 트릭을 이겨 완수. (`TryLeadToFeedTeammate` ↔ `TryReleaseTeammateTarget`이 짝)
4. **안전한 카드(Safest Excluding)** — 위 상황 아니면 목표를 아끼며 트릭을 안 이길 최약 카드.

> **완수 주체는 언제나 임무 주인**, 동료는 카드를 배달하는 역할. feeding이 푸는 건 *"내 타깃이 동료 손에 갇힌 경우"* 뿐 — **내가 약한 타깃을 직접 든 경우는 구조적으로 불가**(한 트릭에 카드 1장).

### 7-4. 확정 튜닝값 (측정으로 결정)
| 항목 | 값 | 근거 |
|---|---|---|
| 탐색상수 C | **0.7** | 스윕 정점: 0.4=32.6% / **0.7=39.8%** / 1.0=33.5% |
| budget | **1000** | 1000 이후 평탄(2000·8000 동일) → 병목은 탐색깊이 아님 |
| 재결정화 K | 5 | 5회당 1회 재샘플 = 다양성·속도 균형 |
| determinizations | 10 | 이상은 한계효용 낮음 |

> **핵심 발견:** budget을 올려도 성능이 안 오른다(평탄) → 품질 천장은 *탐색 깊이*가 아니라 ***롤아웃이 얼마나 협력적으로 잘 두느냐***. 레버는 트리 깊이가 아니라 롤아웃 정책.

### 7-5. 벤치마크 전체
- **단일 태스크(owner-held, Phase1)**: MCTS 46.5% vs RuleBased 23.5%(≈2배). 타깃 값별 구조적 천장 v1~3 ≈10~25%, v9 ≈95%(값↑일수록 쉬움). budget 무관 → **카드 분포의 한계**.
- **다중 태스크(owner-held)**: 2-task MCTS 미션 19.7%/완수 36.2% vs Rule 5.5%/17.0%. 4-task는 all-or-nothing이라 신호 약함(미션 2.3%/완수 24.4%) → **2-task가 최적화 sweet-spot**.
- **협력 시나리오(`cooperativeTargets=ON`, 목표를 전체 덱서 무작위 → helper-held 발생)**:

| 정책 | 미션 성공 | 완수율 |
|---|---|---|
| MCTS (능동 feeding 전) | 29.5% | 46.8% |
| **MCTS (능동 feeding 후, 800미션)** | **34.6%** | **49.9%** |
| RuleBased (HFSM) | 6.7% | 19.0% |
| **격차** | **≈5배** | **≈2.6배** |

  - 능동 feeding으로 **낮은 값 구조적 천장 소멸**(값1 owner-held 8% → 협력 34%). 타깃 보유자별 **helper-held 52% > assignee-held 39%**(동료가 흘려주면 더 쉬움).

### 7-6. 되돌린 실험 (negative results — "측정으로 정했다"의 증거)
| 실험 | 결과 | 왜 실패 |
|---|---|---|
| 엔드게임 완전탐색 | 악화→제거 | **strategy fusion**(결정화별 정확값 평균 → 비현실적 낙관 편향) |
| 셋업(stall) 플레이 | 악화→제거 | owner가 stall하면 동료가 목표 수트를 리드 → **가로채기(interception)** 유발 |
| feeding 우선순위(약한 승리카드 먼저) | 소폭 하락→원복 | 단순 처리 순서가 미세하게 더 나음(900미션) |
| owner-held 천장 돌파(budget/C/솔버/stall 전부) | 모두 실패 | owner-held 39%는 **구조적 천장** → 천장 짜기보다 협력 시나리오가 정답 |

### 7-7. 평가 하니스 / 노브
- **`EvalStats.cs`** — 미션 종료마다 누적 집계해 콘솔 출력: 미션 성공률 + **평균 태스크 완수율**(전부-아니면-전무보다 민감) + 태스크 수별 성공률. 정책 라벨 바뀌면 자동 리셋.
- **평가 노브는 전부 `GameManager` 인스펙터**(MissionManager 필드는 씬 미직렬화라 무시): 표준 벤치마크 = `aiPolicy=MCTS` · `cooperativeTargets=true` · `overrideNumTasks=2` · `mctsBudget=1000` · `mctsDeterminizations=10` · `evaluationLogging=true`.

### 7-8. 다음 레버 / 위치
- 순수 MCTS 튜닝(budget/C/솔버/stall)은 모두 천장에 부딪힘 → 다음 도약엔 **학습된 롤아웃/value network**, 더 정교한 신념 추론(상대 모델링), 또는 RL 에이전트와의 혼합이 필요.

> mcts 브랜치는 통신 토큰 액션/일부 RL 전용 코드(ε-greedy·shaping·보상 정규화)를 덜어내고 MCTS 평가에 집중한 별도 라인.
> 두 라인을 합치면: **RL(학습 가능성) ↔ MCTS(근사 최적 상한) ↔ ceiling_sim(이론적 천장)** 의 3중 비교 체계.

## 8. 핵심 결과 정리

1. **방법론적 성과** — 천장 측정으로 *"과제가 어렵나 / RL이 못 배우나"* 를 분리, **병목을 '드래프트 탐색 부재'로 정량 특정**(RL 38% = 천장 사다리의 랜덤 드래프트 37.8%).
2. **실험적 성과** — 통신(2)·관측(3)·임계값(4)·즉시보상(5)을 차례로 **데이터로 기각**하고, **탐색 강제(ε-greedy, 6)** 가 처음으로 정체를 천장 쪽으로 풀었음(사령관 독점 64%→51%, asuc 25%→34%).
3. **일반화 신호** — 보상 정규화(+1/N) + 혼합 N(7-B)으로 멀티-task에서도 협력 완수율이 N=1 전용을 넘어섬(success_by_assignee ~36%).
4. **남은 갭(정직하게)** — 부분관측 천장 55%까지는 아직 못 갔고, 55→92 갭은 *정책이 아니라 정보(통신이 드래프트엔 못 쓰임)* 문제 = The Crew의 결정불가능성(Coulombe-Lynch)과 맞닿은 **본질적 장벽**.
5. **학습 범위 한정(N=1~4)** — all-or-nothing 보상에서 N≥5 성공 천장 ≈0% → 학습 신호 부재로 의도적 한정. 실제 고N 분포 도달은 정보 갭과 동일한 future work.

## 12. 발표 Q&A 대비 (요약)

- **Q. 왜 게임을 다 안 만들었나?** → 다 만들 수 있고 관측·DB엔 50미션·특수규칙이 다 있다. 다만 *난이도의 본질*은 드래프트+트릭+통신이고 특수규칙은 변주라 연구 질문을 흐린다. 의도적으로 핵심 커널부터 학습했고 확장은 레이아웃까지 준비됨.
- **Q. 성공률 38%면 실패 아닌가?** → 숫자보다 *어디서 온 천장인지*를 측정한 게 핵심. 38%는 '협력은 됐고 드래프트만 랜덤'으로 진단됐고, 탐색을 강제하자 처음으로 그 위로 올라갔다.
- **Q. 왜 MCTS가 아니라 RL인가?** → MCTS/규칙기반은 **천장 측정용 베이스라인**으로 이미 구현해 비교에 쓴다. 연구 질문은 *학습으로 협력이 창발하는가*이므로 MA-POCA가 주 대상.
- **Q. 통신 토큰은 효과 있었나?** → 관측 추가만으론 효과 없음(Run2). Coulombe-Lynch의 제한통신 한계와 정합. 특히 통신은 **트릭 사이에만** 써서 *드래프트(병목)를 못 돕는다*는 게 결정적.
- **Q. N=1~4만 본 게 한계 아닌가?** → 자체 천장 측정상 N≥5는 성공 천장 ≈0%(학습 신호 없음). 신호 존재 범위로 의도적 한정. 모든 미션이 동일 원자 과제(`WinSpecificCard`)의 조합이라 N=1~4가 메커니즘을 대표.
